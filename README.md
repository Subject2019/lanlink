# LanLink 邻传

局域网内互传文本与文件的极简方案：**NAS 上跑一个服务端，手机/平板/电脑打开网页就能用**。

## 为什么这样设计

| | 常见做法（Electron/客户端） | 现在 |
| --- | --- | --- |
| 服务端 | 每台设备各跑一份 | NAS 上一份 5.5MB 静态二进制 |
| 客户端 | 各平台各一个安装包（~100MB 起步） | **浏览器**，零安装 |
| 安卓客户端（可选） | — | 约 80KB 纯原生 APK，不加载网页，自带收发界面 / 环形进度 / 双向系统分享 |
| Windows 客户端（可选） | — | 5.8MB 原生 exe，开机自启、常驻状态栏 + 免浏览器收发窗口 |
| 空闲内存 | 每端 150MB+ | 服务端约 12MB，托盘程序约 10MB |
| 依赖 | Node / Electron / 运行时 | 无运行时依赖，`CGO_ENABLED=0` 纯静态 |

网页界面只有一份（`server/web/`，原生 HTML/CSS/JS，约 20KB，无框架），
浏览器打开即用、改版即时生效。安卓客户端另外有一套**纯原生界面**，直连服务端 API，
不内嵌 WebView、不加载任何网页；Windows 客户端同样有免浏览器的原生收发窗口。

## 现成的包

不想自己编译就直接用 `release/` 里的成品（含 sha256 校验）：

| 文件 | 用途 |
| --- | --- |
| `release/lanlink.fpk` | 飞牛 fnOS 应用包，应用中心「手动安装」 |
| `release/lanlink-android.apk` | 安卓客户端（可选） |
| `release/lanlink-tray.exe` | Windows 托盘程序（可选） |
| `release/lanlink-server` / `-arm64` | Linux 服务端，手动部署用 |

## 安装到飞牛 fnOS

仓库提供已打包好的原生应用（不是 Docker 应用，直接跑二进制）：

```bash
./build.sh fnos          # 产出 dist/lanlink.fpk
```

然后在 fnOS「应用中心 → 手动安装」选择 `lanlink.fpk`。

**安装向导会让你选服务端口和数据目录**（端口默认 8787，数据目录留空用默认共享目录）：
手机/电脑访问用的就是这个端口，桌面图标会自动跟随；装好后在「应用设置」里也能改。
经常传大文件的话，建议安装时就把数据目录选在大容量存储池上，详见下一节。

安装后：

- 桌面出现「LanLink 邻传」图标，点开即用；
- 手机在同一局域网打开 `http://<NAS地址>:<端口>` 即可；
- 日志在 `/var/apps/lanlink/var/app.log`，端口被占用等问题会写在这里；
- 修改端口后需要重启应用生效。

### 数据目录（聊天记录与上传的文件）

默认存在应用共享目录，文件管理器里能看到「LanLink → data」，无需任何设置。

**经常传大文件的话，建议安装时就把数据目录填成空间充足的存储池目录**
（例如 `/vol2/1000/文件/lanlink`），免得默认共享目录所在的存储池被占满。
飞牛不允许应用直接读写用户目录，所以完整流程是：

1. 安装向导里填好想要的目录 → 完成安装（此时不会失败，先照常用默认共享目录）；
2. 应用设置 → **授权目录** → 把这个目录授权给 LanLink；
3. 重启一次应用，启动脚本发现目录可写了，会**自动切过去**，不用再回设置里填一遍。

想换目录：应用设置 → **数据目录** 填新路径（同样要先授权），填 `default` 或留空回默认。
授权前保存会提示「LanLink 无法写入 …」，这不是 bug，是飞牛的目录授权机制拦住了。
生效值写进 `/var/apps/lanlink/etc/settings.conf`：`want_data_dir` 是安装时选的期望目录，
`data_dir` 是当前真正生效的目录；即使期望目录暂时不可写，启动时也会自动回退到共享目录，
并在 `app.log` 里说明原因，不会起不来。改目录不会自动迁移旧数据。

上传前服务端会检查剩余空间，不够就返回「存储空间不足」并拒绝写入，不会留下半个文件；
启动日志里也会记录当前数据目录的可用空间，方便排查大文件上传失败。

**单文件大小上限默认 64GB**（`-max-mb 65536`），足够传十几 GB 的蓝光原盘/录像。
想改：在 `/var/apps/lanlink/etc/settings.conf` 里加一行 `max_mb=131072`（单位 MB）后重启应用，
或在手动部署时用 `-max-mb` / 环境变量 `LANLINK_MAX_MB`。
超限请求会被直接 413 拒绝并说明当前上限；Windows / 安卓客户端会先读 `/api/info` 的
`maxBytes` 做本地预检，超了当场弹提示，不会白传半天才知道失败。

**关于加入码**：fpk 默认以 `-open` 启动，局域网内设备只要填个设备名就能加入（家里用最省事）。
想改成需要加入码：编辑 `/var/apps/lanlink/target/app/cmd/main`，把启动命令里的 `-open` 删掉，
然后 `应用中心 → 停止 → 启动`；此时加入码会打印在 `app.log` 里，访问链接形如
`http://<NAS>:8787/?c=加入码`。

> fpk 包结构遵循飞牛官方 native 应用规范：`manifest` / `config/{privilege,resource}` /
> `app/ui/config` / `cmd/main`（start|stop|status）/ 图标 64+256。

## 手动部署（非飞牛）

```bash
./build.sh server
./dist/lanlink-server -addr :8787 -data ./data        # 前台试跑
sudo ./deploy/install.sh                              # systemd 常驻（Debian/Ubuntu）
```

启动后终端会打印加入码和访问地址。systemd 单元把常驻内存上限设在 256MB（实际约 12MB）。

## 客户端（可选，网页本来就够用）

### 安卓

`release/lanlink-android.apk`（约 80KB）是**纯原生 Java 应用**：界面、网络、传输全部自己实现，
不加载服务端网页，也不需要 WebView / 浏览器内核 / androidx。登录令牌由 App 自己保存，
通过 `lanlink_token` Cookie 直连 REST 接口，用 SSE 长连接即时收消息（另有 5 秒兜底轮询）。

- **原生收发界面**：消息列表、文本输入、加入页、在线设备条都是 Android 原生控件；
  自己的消息靠右、别人的靠左，点文件下载、长按出菜单（复制 / 分享 / 删除）。
- **传输进度**：上传和下载时，文件卡片旁边显示**环形进度条**（总大小未知时显示旋转弧），
  底部另有整批文件的汇总进度条。上传带 `Content-Length`，服务端会先检查剩余空间，
  空间不足直接返回「存储空间不足」，而不是写到一半才失败。
- **权限与目录**：设置页可授予通知权限（Android 13+）、查看登录状态、改设备名、分享服务地址；
  用 `ACTION_OPEN_DOCUMENT_TREE` 授权目录后下载直接写进去，否则写系统「下载」目录
  （MediaStore，无需存储权限）。不需要「所有文件访问」权限。
- **多选文件**：「+」调起原生文件选择器，一次选多个，逐个流式上传并发通知。
- **被其他应用分享**：在相册、文件管理器、浏览器里把文本 / 单文件 / 多文件分享到
  「发到 LanLink」——文本发成一条消息，文件批量上传。还没加入时先暂存，加入后自动补发。
- **分享到其他应用**：文本直接调系统分享面板；文件先用原生网络层下载到缓存，
  再由自己实现的 `ShareProvider` 以 `content://` 交给目标 App。
- 启动时 UDP 广播自动发现 NAS，找不到再手填地址；免加入码模式下自动隐藏加入码输入框。

### Windows 客户端（托盘 + 原生窗口）

`release/lanlink-tray.exe`（5.8MB，纯 Go，不内嵌浏览器内核，也不需要 .NET / WebView2）：

- **原生窗口**：双击托盘图标或点「打开 LanLink 窗口」，**不用打开浏览器**就能收发。
  新消息由 SSE 即时推送、另有每 3 秒兜底同步；输入框发文本；「发送文件…」可一次多选，
  文件也能**直接拖进窗口**批量上传；
  选中文件消息点「下载选中」（或双击）即可保存到本机任意位置。
- **传输进度条**：上传（含拖放、托盘批量发送）和下载时，输入框下方会出现系统原生水平进度条，
  右侧实时显示百分比与「已传/总大小」。几百 MB 的大文件也能看到在动，不再是长时间没反应；
  拖进去会立刻提示「已收到 N 个文件」，上传前先读 `/api/info` 的 `maxBytes` 预检大小，
  超限或失败都用弹窗列出原因；上传带 `Content-Length`，服务端也会提前检查剩余空间。
- **托盘快速发送**：不打开窗口也能从托盘菜单直接选文件（可多选）上传。
- **免浏览器登录**：窗口自己调 `/api/join` 拿设备令牌并存进配置文件。服务端免加入码时全自动，
  需要加入码时填一次，之后重开不用再输。
- 常驻状态栏，菜单可勾选 **开机自动启动**（写 `HKCU\...\Run`）、复制访问地址、
  重新自动发现 NAS、编辑配置文件；「在浏览器中打开」保留为备用入口；
- 每 60 秒探一次服务端状态，托盘提示与菜单里显示在线/离线；
- 单实例保护，重复启动静默退出；配置在 `%APPDATA%\LanLink\config.json`
  （`server` / `token` / `name` / `autostart`）。

窗口是手写 Win32 控件（窗口类 + Edit/ListBox/Button/ProgressBar + 系统文件对话框 + 拖放），
没有引入 GUI 框架，exe 体积和内存占用跟「只有托盘」时基本一致。

不装也完全不影响使用，直接浏览器打开 `http://<NAS>:<端口>` 即可。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/info` | 公开信息（是否免加入码、版本、`maxBytes` 单文件上限） |
| POST | `/api/join` | 加入并换取设备 Cookie |
| GET | `/api/state` | 设备列表 + 最近 500 条消息 |
| GET | `/api/events` | SSE 长连接，推送新消息/设备变化 |
| POST | `/api/messages` | 发送文本 |
| PUT | `/api/files?name=x` | 流式上传文件（请求体就是文件） |
| GET | `/api/files/{id}?n=x` | 下载文件 |
| DELETE | `/api/messages/{id}` | 删除自己的记录 |
| POST | `/api/device` | 修改自己的设备名 |

自动发现：UDP 8788，发送 `lanlink.discover`，服务端回 `{"v":1,"port":8787}`，
客户端用应答包的源 IP 拼地址，因此不需要任何配置。

```
  web/                  index.html / style.css / app.js

```

## 资源占用实测

| 项 | 数值 |
| --- | --- |
| 服务端二进制 | 5.5MB（静态链接，无依赖） |
| 服务端常驻内存 | ~11.6MB |
| 飞牛 fpk 安装包 | 2.4MB |
| Android APK | 约 80KB |
| Windows 托盘 exe | 5.8MB |
| 前端资源 | 约 20KB |

事件推送用 SSE：没有新消息时服务端不产生任何轮询和 CPU 开销，空闲连接只占一个 goroutine。
